# Milwaukee Covered Buildings · 3D dashboard

A 3D map of the 826 buildings on the City of Milwaukee covered-buildings list. It shows who owns
each building, which buildings share an owner, and the contact-research status of each — color-coded
so the team can see coverage at a glance.

Plain HTML + JavaScript, **no build step**. deck.gl 9.4.0 + MapLibre GL JS 5.24.0 (pinned, from unpkg).
Every map source is keyless: OpenFreeMap Positron style + OpenMapTiles vector tiles for the basemap and
the white 3D city, AWS Terrain Tiles for the hillshade.

## Run locally

The two data files live in `data/` (generated by `../pipeline/build_data.py`). Serve the folder over
HTTP — opening `index.html` as a `file://` URL will not work because the browser blocks `fetch`:

```bash
cd map
python3 -m http.server 8080
# open http://localhost:8080
```

Locally there is no access gate (whoever runs it already has the data files). On the hosted site,
`middleware.js` gates every request.

## Data files (`data/`)

- `milwaukee_data.json` — `{ meta, buildings[], entities[] }`. One row per building, one entity per owner.
- `milwaukee_lots.geojson` — footprint polygons, `properties.id` links to the building `id`.

Both are produced by the pipeline from the City Excel; see `../pipeline/`.

## Hosting (Vercel)

`middleware.js` gates the whole site with a shared access code and gates CSV exports with a second code.
Set these environment variables on the deployment:

- `ACCESS_CODE` — the team access code (typed at the gate)
- `SESSION_SECRET` — a long random string used to sign session cookies (≥ 16 chars)
- `EXPORT_CODE` — a second code that unlocks CSV exports for 8 hours

If `ACCESS_CODE` or `SESSION_SECRET` is missing the site fails closed (refuses every request).
